# 地区地图开发方向

## 定位

地区地图是 LifeSpace 云端能力的一部分，用于按地区发现真实种植项目、公开经验和地区差异。

它不是单独的一级板块，而是“发现”的另一种查看方式。

## 已确认方向

### 入口

- 放在“发现”页。
- 不占用底部一级导航。
- 不和“种植 / 农法设施 / 虫鱼生态 / 其他”等内容分类混在一起。
- 可采用“列表 / 地图”切换或发现页顶部地图入口。

### 用户权限

- 本地免费用户：可看到入口和功能说明，但不能完整使用地图。
- 云端试用用户：地图单独提供一次完整体验。
- 地图体验期：14 天。
- 建议从账号第一次主动进入地图时开始计时，而不是从领取 90 天云端试用当天开始。
- 正式 Plus 用户：持续使用地图。
- 地图体验结束后保留入口和轻量预览，用于说明云会员价值。

### 地区数据

- 地图与“种植地址 / 种植地区”直接关联，不读取用户账号所在地作为项目依据。
- 账号保留一个“默认地区 / 常用地区”，用于新建项目时自动带入。
- 每个种植项目必须有自己的种植地区。
- 新建项目默认继承账号默认地区，但允许用户修改。
- 一个用户可以维护不同地点的多个项目。

### 隐私

- 不公开家庭精确地址、门牌、小区或精确住宅坐标。
- 公开地图只显示适当的地区级位置，如城市或区县。
- 可采用区域聚合点，而不是在用户住所精确打点。

## 第一版建议范围

第一版保持轻量：

- 世界 / 地区地图
- 国家、地区 / 省州、城市层级
- 植物筛选
- 地区筛选
- 月份筛选（如数据条件允许）
- 地图聚合点
- 点击地区后查看当地公开项目 / 经验
- 与现有发现卡片体系衔接

不在第一版中做：

- 复杂全球气候模型
- 实时天气驱动建议
- 大规模历史气候数据库
- 精确家庭位置展示

## 后续演进

数据积累后逐步增加：

1. 地区 × 植物 × 月份的真实经验统计
2. 当地高频问题与常见操作
3. 相似气候地区推荐
4. 气候区 / 耐寒区 / 霜期等辅助信息
5. 地区化实操指引
6. “在你这里怎么种”的个性化地区知识入口

## 成本原则

- 第一阶段优先利用现有 Supabase / PostgreSQL 数据结构扩展。
- 前端地图使用正规地图服务，避免依赖不适合商业大规模使用的公共免费瓦片。
- 几千名云会员规模下，优先控制在低成本或免费额度范围内。
- 不因地图功能提前引入复杂的大陆独立基础设施。

## 产品目标

地图不是为了展示“哪里有人”，而是逐步成为：

> 按地区找到真实种植经验，并理解同一种植物在不同环境中的差异。

长期目标是形成 LifeSpace 很有辨识度的能力：

> 不是只告诉用户植物怎么种，而是告诉用户“在这里怎么种”。
