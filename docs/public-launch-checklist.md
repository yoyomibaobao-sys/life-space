# 正式公开前检查清单

本清单用于从“熟人小范围测试”切换到“面向不特定公众推广、注册或收费”。在所有必做项完成并复核前，保持：

- `SEARCH_INDEXING_ENABLED=false`
- 不向陌生用户推广
- 不开放正式收费
- 不把公开前数据库迁移直接用于生产库

## 一、运营者需要先确定的事项

### 1. 正式域名

1. 购买并确定唯一正式域名。
2. 在 Vercel 项目的 `Settings → Domains` 添加域名，并按页面要求配置 DNS。
3. 把最终域名提供给开发者，用于更新 `NEXT_PUBLIC_SITE_URL`、Supabase Site URL、允许的 Redirect URLs、Android 服务地址和邮件链接。
4. 在正式域名生效前，不开启搜索引擎收录。

参考：[Vercel 添加自定义域名](https://vercel.com/docs/domains/working-with-domains/add-a-domain)

### 2. 经营主体与收款决定

准备并确认以下真实资料：

- 经营主体类型：个人、个体工商户或公司
- 主体法定全称
- 营业执照或其他登记信息；有许可要求时还包括许可证信息
- 对外客服邮箱，以及需要公开的其他联系方式
- 收款账户主体名称，及其与网站经营主体的关系
- 是否面向中国大陆用户开放人民币收费

资料未确定时，会员付款页只能用于内部测试。正式收费前需由熟悉服务地区、主体类型和跨境处理的专业人员复核公示与资质要求。电子商务经营者通常需要在首页显著位置持续公示主体信息或其链接，见[《中华人民共和国电子商务法》第十五条](https://www.cac.gov.cn/2018-09/01/c_1123362506.htm)。

### 3. 公开测试内容

逐项判断“发现”中的 `R`、`000` 等内容：

- 是真实内容：改成能被访客理解的标题和封面。
- 是测试内容：由内容所有者改为私密或移入回收站。
- 无法确认所有者：记录项目名称和链接，交由管理员核对；不要直接批量删除。

## 二、账号和邮件后台设置

### 1. 先配置正式 SMTP

Supabase 默认邮件服务只适合测试，目前只向项目团队预授权地址发送，且有很低的发送限额。正式注册前应：

1. 选择支持 SMTP 的事务邮件服务商。
2. 在正式域名配置 SPF、DKIM、DMARC。
3. 在 Supabase `Authentication` 设置中启用 Custom SMTP，填写主机、端口、用户名、密码、发件地址和显示名称。
4. 禁用邮件服务商的链接跟踪，避免改写确认链接。
5. 用一个不属于 Supabase 项目团队的真实邮箱，分别测试注册确认、重发确认和忘记密码。

SMTP 密码只直接填写到 Supabase 后台，不发到聊天、不提交到 Git。

参考：[Supabase Custom SMTP](https://supabase.com/docs/guides/auth/auth-smtp)

### 2. 再开启邮箱确认与密码保护

在生产 Supabase 的 Auth 设置中确认：

- 邮箱确认开启。
- 最低密码长度至少 8 位；可接受时要求数字、大小写字母和符号。
- Secure password change 开启。
- 如果套餐支持，开启 Leaked password protection。
- 检查 Auth Rate Limits，先采用保守限额，再根据真实发送量调整。

必须先确认正式 SMTP 可以送达，再依赖邮箱确认分配正式账号编号和首批体验名额。参考：[Supabase 密码安全](https://supabase.com/docs/guides/auth/password-security)、[Supabase Auth Rate Limits](https://supabase.com/docs/guides/auth/rate-limits)。

### 3. 按顺序开启 Cloudflare Turnstile

代码已经支持可选 Turnstile，未配置时保持隐藏。启用顺序必须是：

1. 在 Cloudflare Turnstile 创建站点，允许当前 Vercel 域名和最终正式域名。
2. 把公开 Site Key 填入 Vercel 环境变量 `NEXT_PUBLIC_TURNSTILE_SITE_KEY`，先部署并确认注册、登录、重置密码和重发确认页都显示安全验证。
3. 把 Secret Key 直接填入 Supabase `Authentication → Bot and Abuse Protection`，选择 Turnstile 并启用。
4. 立即用真实浏览器走完注册、登录、忘记密码和重发确认四条流程。

不要先在 Supabase 强制开启 CAPTCHA 再部署前端，否则现有登录流程会被拒绝。Secret Key 不发到聊天，也不能放进 `NEXT_PUBLIC_*` 环境变量。

参考：[Supabase CAPTCHA 设置](https://supabase.com/docs/guides/auth/auth-captcha)

## 三、数据库发布顺序

由开发者执行，不由运营者在 SQL Editor 手工粘贴：

1. 草稿 PR 的隔离数据库 CI 全部通过。
2. 生产数据库创建可恢复备份，并记录迁移前版本。
3. 确认正式 SMTP 和邮箱确认已经启用。
4. 依次应用权限收口迁移和“邮箱确认后分配正式账号”迁移。
5. 验证匿名游客仍能浏览公开内容，但不能写表、调用内部函数或读取私密数据。
6. 用非团队邮箱注册：确认邮件前不得获得正式编号或占用首批名额；点击确认后才分配。
7. 验证现有账号、管理员、公开指引、经验卡、集市和付款后台没有回归问题。

## 四、跨境与隐私事项

现有代码已增加单独的跨境选择和版本化同意记录，但页面文案不能替代完整合规判断。正式面向中国大陆用户前，至少需要：

1. 确认个人信息处理者的真实名称和联系方式。
2. 确认境外接收方、联系方式、处理目的、方式、信息种类及用户行使权利的路径。
3. 确定适用的跨境条件或豁免，并完成所需文件或程序。
4. 对跨境提供进行个人信息保护影响评估，保存评估报告和处理记录。
5. 让专业人员复核隐私说明、单独同意、服务地区和实际数据流一致。

[《个人信息保护法》第三十八、三十九条](https://www.cac.gov.cn/2021-08/20/c_1631050028355286.htm)分别涉及跨境条件和单独告知同意；第五十五、五十六条涉及事前影响评估及记录保存。仅勾选“单独同意”并不等于其他跨境义务已经完成。

## 五、最终公开闸门

只有以下项目全部通过，才进入正式公开：

- 正式域名、邮件、验证码和四条账号流程通过真机测试。
- 隔离数据库 CI、生产迁移和游客权限复核通过。
- 经营主体、公示、收款资格和跨境方案已经确认。
- 公开测试内容已清理，法律页中的主体与联系方式为真实资料。
- 支付宝和 PayPal（如保留）各完成一笔真实付款、开通、退款全流程测试。
- 手机中文、手机英文、桌面中文、桌面英文均完成匿名与登录状态验收。

最后一步才把生产环境的 `SEARCH_INDEXING_ENABLED` 改为 `true` 并重新部署。开启后再次检查 `robots.txt`、页面 robots 元数据和 `X-Robots-Tag`；在此之前不得把“网站可访问”当成“已经适合公开”。
