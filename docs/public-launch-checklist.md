# 正式公开前检查清单

本清单用于从小范围测试切换到面向不特定公众推广、注册或收费。在所有必做项完成并复核前，保持：

- `SEARCH_INDEXING_ENABLED=false`
- 不向陌生用户大范围推广
- 不开放正式收费
- 不把草稿中的数据库迁移未经验证直接用于生产库

## 一、正式域名与部署

1. 确认唯一正式域名及 DNS 管理位置。
2. 当前仍由 Vercel 提供生产部署时，在 Vercel 配置正式域名；完成 Cloudflare 迁移后，以 Cloudflare 的最终配置为准。
3. 正式域名确定后同步更新：
   - `NEXT_PUBLIC_SITE_URL`
   - Supabase Site URL 与允许的 Redirect URLs
   - Android 服务地址
   - 注册确认、密码重置等邮件链接
   - Cloudflare Turnstile 允许域名
4. 正式域名、登录回调和邮件链接未全部通过前，不开启搜索引擎收录。

## 二、账号、邮件与验证码

### 1. 正式 SMTP

正式开放注册前：

1. 使用支持 SMTP 的事务邮件服务商。
2. 为正式域名配置 SPF、DKIM、DMARC。
3. 在 Supabase Authentication 中启用 Custom SMTP。
4. 禁用会改写确认链接的邮件链接跟踪。
5. 用一个不属于项目团队的真实邮箱测试：注册确认、重发确认、忘记密码。

SMTP 密码只保存在服务商或 Supabase 后台，不写入 Git，也不放入公开环境变量。

### 2. Supabase Auth 设置

生产项目确认：

- 邮箱确认开启。
- 最低密码长度至少 8 位。
- Secure password change 开启。
- 如当前套餐支持，开启 Leaked password protection。
- Auth Rate Limits 与实际 SMTP 配额匹配。

当前账号规则：

- 注册成功即建立永久账号及账号编号。
- 邮箱确认后用户才能正常登录。
- 邮箱确认并登录后，每个正式账号可主动领取一次 30MB 云端体验。
- 体验从领取日起 90 天有效；到期后还有 90 天处理期。
- 注册、邮箱确认和领取体验都不会自动上传或公开用户已有本地内容。

### 3. Cloudflare Turnstile

代码支持可选 Turnstile。启用顺序：

1. 在 Cloudflare Turnstile 创建站点，并允许当前预览/生产域名和最终正式域名。
2. 在当前部署平台配置公开的 `NEXT_PUBLIC_TURNSTILE_SITE_KEY`，部署后确认注册、登录、忘记密码、重发确认页面都显示安全验证。
3. 将 Secret Key 直接配置到 Supabase `Authentication → Bot and Abuse Protection`，选择 Turnstile 并开启 CAPTCHA。
4. 立即用真实浏览器复测四条账号流程。

不要先在 Supabase 强制开启 CAPTCHA、再部署前端；否则现有登录请求会被拒绝。Secret Key 不得放入 `NEXT_PUBLIC_*`。

## 三、数据库发布顺序

由开发流程执行，不在生产 SQL Editor 中临时手工拼接：

1. PR 的静态 SQL 检查、隔离数据库测试和应用构建全部通过。
2. 记录生产数据库当前迁移版本，并确认可恢复方案。
3. 应用“注册法律同意记录”迁移。
4. 应用“公开数据库权限收紧 v2”迁移。
5. 再次运行 Supabase Security Advisor。
6. 验证匿名游客：
   - 可以浏览应公开的项目、记录、经验卡、集市和公开资料；
   - 可以产生允许的匿名浏览统计；
   - 不能新增/修改/删除业务数据；
   - 不能直接执行登录用户、管理员、触发器或维护 RPC。
7. 验证普通登录用户仍可：
   - 领取一次云端体验；
   - 查看自己的会员/体验状态；
   - 新建和维护自己的云端内容；
   - 使用回收站、转私密、结束集市发布等本人操作。
8. 验证管理员页面仍能读取和处理会员、付款、退款、账号及运营数据。

## 四、体验到期规则复核

正式公开前至少用测试账号覆盖以下状态：

1. 未领取：显示一次性 30MB / 90 天体验入口。
2. 已领取且有效：按 30MB 容量和到期日使用。
3. 体验到期进入处理期：以网页内提醒为主，允许升级、导出或逐项转回本地。
4. 处理期结束：回到本地使用；需要停止仍在云端公开/互动的状态。
5. 云会员到期：云端内容长期只读保留，并可多次下载到本地；不得与免费体验处理期混淆。

## 五、隐私、跨境与公开资料

正式面向公众前确认：

- 隐私说明、服务条款、退款规则、运营联系信息与实际产品一致。
- 注册页服务/隐私同意与单独的跨境处理同意均可正常记录。
- 法律版本号与当前上线文案版本一致。
- 对外运营主体、客服邮箱及需要公示的信息均为真实资料。
- 境外服务商、处理目的、信息种类、用户权利路径与实际数据流一致。
- 正式收费和跨境处理方案在需要时完成专业合规复核。

## 六、内容与付款验收

公开前：

- 清理或私密化 R、000 等旧测试内容；不要误删无法确认所有者的真实内容。
- 公开项目、记录、经验卡和集市信息均使用访客能理解的标题、封面和状态。
- 支付宝和 PayPal（如正式保留）各完成至少一次真实的付款、开通、退款闭环测试。
- 付款成功、退款、会员到期后的状态在用户页和管理员页一致。

## 七、最终公开闸门

只有以下项目全部通过，才进入正式公开：

- 两套生产/预览构建成功，无阻断性 CI 错误。
- 正式域名、SMTP、邮箱确认、8 位密码策略、Turnstile 均已真实启用并验证。
- 数据库新迁移已部署，匿名/普通用户/管理员三类权限复核通过。
- 30MB / 90 天手动领取体验及 90 天处理期规则通过状态测试。
- 经营主体、公示、收款和跨境事项已经确认。
- 手机中文、手机英文、桌面中文、桌面英文均完成匿名与登录状态验收。

最后一步才把生产环境 `SEARCH_INDEXING_ENABLED` 改为 `true` 并重新部署。开启后再次检查 `robots.txt`、页面 robots 元数据和 `X-Robots-Tag`。在此之前，“网站可以打开”不等于“已经适合正式公开”。
