## 当前基线

- Android single-runtime 核心逻辑已完成本轮代码收口：统一 bundled 登录、云端离线缓存、pending 手动上传、本地项目主动上传云端、Follow 正式页面等。
- 当前 PR #95（`integrate-android-local-first-after-cache`）仍为 Draft，隔离工作树含未提交的 QA 收口修改；实际 HEAD 和未提交状态须在每轮执行前核对。尚未合并、部署或正式发布。
- 后续 Android 页面调整采用“小步修改 → 立即预览／真机查看 → 再调整”，不再一次性大批量改 UI。
- PayPal 一次性 US$8 年费自动开通的核心代码已存在。2026-10-11 只读核查：生产 Supabase 迁移历史含 `add_paypal_auto_membership`，付款表有 PayPal 订单／捕获字段和各自唯一索引，绑定与确认 RPC 不向 `anon`／`authenticated` 开放；7 项定向自动测试通过。但正式站 `/api/paypal/status` 返回 `enabled:false`，不能据此区分开关与服务端配置缺项；完整 RLS、Sandbox、Live Webhook、真实付款／退款仍待验收，收费发布门禁未通过。
- 当前不做自动续费。

## 2026-10-15 简约设计与管理员治理优先级

本节为最新已确认的首发范围，优先于下文五区间批量清理早期设想；**写入计划不等于完成或上线**。

- 大道至简、最小实现：复用现有功能，核实后才精简重复入口和不必要步骤；不整页重做、不丢失原有筛选、卡片、导航、图片与数据行为。
- 后台优先显示用户／会员、付款退款、实际空间占用、公开内容、举报和处理记录。先审查现有七分区会员后台与独立举报页，按需整理信息层级，不新建平行系统。
- 在社区与集市正式开放前补齐最小内容治理：处理举报、删除违规发言、违规公开内容下架与恢复、必要用户评论／发布权限限制；一律服务端授权、留操作记录，先隔离验收。
- 30MB／90天体验结束后30天处理期仍可备份及逐项目保存；期满仅关闭原体验资料访问，不自动物理删除。存储需要时再由管理员决定手动清理；已成功付费且未撤销的用户永久排除免费体验清理，清理前付费恢复仍在资料，Plus 到期长期只读。
- PR #95 未上线的五区间清理、物理删除任务和迁移原样保留并冻结，不作为首发门禁，不运行、不解锁；正式发布前单独核验旧自动清理停用、用户权限限制、Plus 恢复，并保留正常 Storage 和 Cron 维护。

## 正式收费发布主线

不设置独立的免费试运营或邀请制免费发布阶段。注册账号可主动领取的30MB／90天云体验属于产品权益，本地空间永久免费。当前仍在隔离 QA 收口，以下为顺序和门禁，不表示已经完成或授权生产变更。

1. Android 与数据安全：收口 PR #95 真机、SAF 恢复、离线一致性、登录及页面回退；保留已通过的多图 ZIP 证据。
2. Cloudflare 正式运行环境：核实正式域名、Worker、R2、Supabase Storage、邮件、环境变量与 Cron，防止 QA／生产混用及重复任务。依赖审计可与 Android 验收并行，生产切换单独执行。
3. 正式收费闭环：PayPal Orders v2、Capture、签名 Webhook、幂等开通与退款、Sandbox、生产迁移安全核对、Live 真单；支付宝凭证及管理员核实。
4. 正式发布门禁：注册邮件／SMTP、Turnstile、会员生命周期、导入备份恢复、支付、权限和安全、法律合规、正式 APK 升级签名及资料保留、监控和故障恢复全部通过，形成验收报告等待用户批准。
5. 经用户明确批准后直接正式收费发布，再观察运行并处理故障；不先开放未验收的免费站点或支付。未经批准不合并 PR #95、不切换生产、不发布正式 APK。

以下工作项记录具体实施与验收内容，不能把编号解释成另一套上线阶段。

## 阶段 2：SAF 本地资料目录、恢复与分组收口

**状态：PR #95 隔离 QA 验证中；尚未正式发布。** SAF 核心、独立本地项目持久化和旧资料恢复已有实现与专项验证；本轮固定默认目录引导、用户说明及分组保存仍需逐项核对和验收，不以计划代替完成记录。

目标：

- 新本地空间默认目标为内部存储 `Documents/LifeSpace`，App 不提供位置切换设置；由 Android 系统选择器完成用户确认并持久授权。系统预定位和目录创建能力须按 Android 10／11+ 真机证据判断，不能绕过授权。
- 既有 SAF 目录和 `localSpaceId` 优先保留；重装后允许重新授权原目录，不静默迁移、覆盖或创建第二个空空间。
- SAF 已验证提交为本地创作资料 source of truth；IndexedDB 只作运行时镜像、索引和缓存。云 cache／pending 按账号分区，本地资料与登录状态解耦。
- 本地记录的拍摄和相册照片都归档为可随项目、记录恢复的 SAF 媒体；不触碰相册原图。
- 用户信息中的“数据与安全”显示真实连接位置、卸载保留和手动删除说明；分组设置页只保留层级开关，具体分组在我的空间维护，持久化失败不误报成功。
- 「启用本地空间」是本机显示偏好，默认开启，只由用户切换并保持；关闭只隐藏本地项目和相关入口，不删除 SAF 资料，也不影响云端离线缓存与待同步。我的空间来源和「＋项目」、底部「＋」的选择项目按该开关与登录状态显示；Android 可见来源左对齐，「＋项目」固定在右侧。网页来源栏不套用该排列。本条是规则，真机八态尚未记为通过。

必须覆盖：授权取消、未知目录、既有目录兼容、权限失效、空间不足、中断重试、hash／关系验证、登录切换、覆盖安装、卸载重装、相册照片恢复及分组失败重试。测试使用隔离目录，不修改原 SAF 资料。

完成条件：Android 10 与 11+ 能可靠授权或明确报告限制；QA 真机项目、记录、照片、分组及 `localSpaceId` 在覆盖升级与卸载重装后恢复；系统文件管理器可见资料；受保护页面与云功能无回退。未实测项保留为待验收。

## 阶段 5：会员生命周期闭环

**状态：阶段4前可准备，正式收费前必须完成。**

### 注册与体验

- 正式注册账号邮箱确认后可主动领取一次 **30MB / 90天** 云体验。
- 注册本身不自动领取、不自动上传。
- Android 在“我 → 用户信息”标题下方保留云试用领取／状态操作，文字明确为“开通90天云端试用”；云空间入口始终显示，不受本地开关和云权益状态影响。游客／普通注册用户的云空间引导，以及本地项目转云受限时，分别展示“开通90天云端试用”和“升级Plus会员”两个入口；已用过或不符合试用资格者只保留适用 Plus 入口。两入口复用同一 App 内试用领取／Plus 开通流程，不自动上传本地内容。网页版原有入口保留。
- 90天自然到期，或用户主动提前结束时，云端立即停止新增、编辑、上传、互动和发布，进入只读。提前结束需服务端原子校验并从实际结束时启动30天处理期，重复请求不能延长；不影响 Plus、历史付费保留或旧测试账号。
- “我的空间”标题下一条紧凑提醒：有效体验最后7天显示剩余天数与备份入口，不开放项目复制；处理期显示准确剩余天数与备份入口，允许从项目菜单逐个复制。以服务端时间为准，不向普通用户或 Plus 展示。

### 30天处理期

- 体验自然到期或主动结束后的处理期为 **30天**。
- 到期当天持续显示“云端体验已结束／只读”和处理期限，不做多轮消息提醒。
- 只在处理期结束前 **7天** 额外提醒一次。
- 正式 SMTP 上线后，可在同一“最后7天”节点同步发送一封关键邮件，不再发送其他处理期邮件。
- 处理期内允许：开通 Plus、备份导出、从本人云项目菜单逐个“保存到本机（复制）”；不自动转移或清除云端原件。
- 处理期结束后，未付费账号原体验云资料立即不可访问，但不自动物理删除；账号、资料、付款记录和本地 SAF 数据保留。未实际清理前开通 Plus，可恢复原云项目、记录和照片；清理完成后无法承诺恢复。

### 历史方案：五区间管理员清理（2026-10-15 确认延期，非首发任务）

**以下仅为 PR #95 未提交开发成果和安全审计历史，不再作为当前实施任务。** 现有代码、迁移和测试均保留，管理员执行入口继续锁定，禁止运行相关迁移或生产清理。容量真正需要时另行确定最小方案，不因历史计划自动继续开发。

- 在“用户管理 → 过期云端资料清理”设置五个时间区间，均以**30天处理期结束时间**为基准：结束后未满6个月、6个月至未满1年、1年至未满3年、3年至未满6年、6年以上；允许多选。管理员选择的是待清理的完整时间区间，不设置每次最多清理账号数量，未选择区间不执行清理。
- 清理前只统计处理期已结束且从未成功付费的体验账号，展示待清理账号、项目、照片数量及占用空间，必须由管理员确认；无需设定强制清理年限。待清理资料继续计入云端实际容量和安全预算。
