# LifeSpace 产品与发布路线图

更新日期：2026-10-01

本文件只维护阶段、顺序、当前状态和完成条件。具体产品规则以根目录 `AGENTS.md` 为准；权限细节见 `docs/membership-access.md`；正式公开门槛见 `docs/public-launch-checklist.md`。

## 当前基线

- Android single-runtime 核心逻辑已完成本轮代码收口：统一 bundled 登录、云端离线缓存、pending 手动上传、本地项目主动上传云端、Follow 正式页面等。
- 当前 integration 基线以 `integrate-android-local-first-after-cache` 的实际最新远端 HEAD 为准，不在路线图固定旧 SHA。
- 后续 Android 页面调整采用“小步修改 → 立即预览／真机查看 → 再调整”，不再一次性大批量改 UI。
- PayPal 一次性 US$8 年费自动开通的核心代码已经存在，但生产 migration、Sandbox、Live Webhook 和真单闭环尚需正式验收。
- 当前不做自动续费。

## 阶段 1：Android 页面与导航视觉收口

**状态：下一步。**

范围：

- Profile / 用户信息页仍跳网页的一级入口逐项收回 APP 内；真正 Web-only 的最终二级动作才允许外跳。
- 删除用户信息页下方重复的“收到有用”“经验卡”入口，保留顶部统计入口并连接对应 bundled 页面。
- Follow、我的空间、待上传区、本地／云端卡片、详情页、返回行为、间距、字号和按钮位置按真机效果小步调整。
- 逻辑主链默认冻结：不主动重构 auth、connectivity、pending sync、cloud cache、local-to-cloud transfer。

完成条件：

- 主要页面不出现明显重复入口或无必要网页跳转。
- 手机中文／英文下布局可用。
- 每组 UI 修改都经过预览或真机确认。

## 阶段 2：用户可访问的本地资料与备份

**状态：待阶段1视觉结构稳定后推进，可与后半段UI并行。**

目标：

- App 私有存储继续作为运行数据库、索引和缓存底座。
- Android 通过系统文件选择器让用户选择并长期授权外部资料目录，建议引导 `Documents/LifeSpace`。
- “备份与导出”、用户主动保存的资料、未来“全部保存到本地”复用该目录能力。
- 用户可以通过系统文件管理器看到已经导出／保存的资料。
- 外部目录不作为实时运行数据库，不建立自动双向同步。

必须覆盖：

- 目录权限失效；
- 空间不足；
- 中断与重试；
- 幂等保存；
- 恢复／导入；
- 重复导入；
- 卸载 App 后不主动删除外部保存资料。

完成条件：

- 真机上可选择目录、导出、查看、重新导入。
- 不影响现有本地项目和云缓存。
- 升级安装不丢资料。

## 阶段 3：Android single-runtime 正式合并与发布基线

**状态：阶段1、2完成后。**

步骤：

1. 完整 Android acceptance。
2. 覆盖安装验证：保留已有本地项目。
3. 无网冷启动、登录／退出／重新登录。
4. pending 云内容手动上传。
5. local-only 主动上传云端。
6. 外部备份／恢复。
7. 中英文和系统返回。
8. 创建 PR，合并主线。
9. 生成正式 signed APK，保持永久签名。

完成条件：

- 主线成为 Android single-runtime 唯一正式实现。
- integration 不再长期漂移。

## 阶段 4：PayPal 一次性付款自动开通上线

**状态：核心代码已存在，待部署与真实验收。**

当前产品规则：

- US$8 / 12个月；
- 一次性付款；
- 付款成功自动开通／顺延 Plus；
- 1GB 云空间；
- 30 条集市“发布中”额度；
- 不自动续费。

上线顺序：

1. 核对生产数据库是否已应用 PayPal 自动会员 migration。
2. 核对部署端 PayPal / Supabase secrets 和 `PAYPAL_SITE_ORIGIN`。
3. Sandbox 全流程：创建订单 → PayPal 支付 → return → 自动开通。
4. 测“付款后直接关闭页面”，确认 Webhook 仍能补开通。
5. 重放 return / webhook，确认不重复延长。
6. 错金额、错币种、错订单、未绑定订单、capture 冲突均拒绝。
7. Sandbox 通过后切 Live App / Live Webhook。
8. 做一笔真实 US$8 开通并核对会员、容量和集市额度。
9. 做真实退款闭环。

支付宝当前继续：

- ¥64 / 年；
- 经营／商家收款码；
- 用户上传凭证；
- 管理员核实后确认；
- 暂不接支付宝自动支付接口；
- 暂不接微信支付。

## 阶段 5：会员生命周期闭环

**状态：阶段4前可准备，正式收费前必须完成。**

### 注册与体验

- 正式注册账号邮箱确认后可主动领取一次 **30MB / 90天** 云体验。
- 注册本身不自动领取、不自动上传。
- 90天到期当天立即停止云端新增、编辑、上传、互动和发布，已有内容进入只读。

### 30天处理期

- 体验到期后处理期为 **30天**。
- 到期当天持续显示“云端体验已结束／只读”和处理期限，不做多轮消息提醒。
- 只在处理期结束前 **7天** 额外提醒一次。
- 正式 SMTP 上线后，可在同一“最后7天”节点同步发送一封关键邮件，不再发送其他处理期邮件。
- 处理期内允许：开通 Plus、导出、全部保存到本地。
- 处理期结束后，只清理从未付费体验账号仍留在云端的体验数据；账号、资料、付款记录和本地数据保留。

### Plus 到期

- Plus 到期后云端长期只读保留。
- 允许查看、导出、删除、公开转私密及“全部保存到本地”。
- 禁止新增、编辑、上传、互动、重新发布及私密转公开。
- 续费后恢复云端写入与同步。
- 曾有成功付费记录的账号永久退出免费体验自动清理流程。

### 全部保存到本地

入口：

`我 → 用户信息及设置 → 备份与导出 → 全部保存到本地`

要求：

- Plus 到期后显示；
- 云体验到期30天处理期复用同一底层机制；
- 按项目幂等、可续传、可重试；
- 检查本机空间；
- 显示待保存／保存中／已保存／失败；
- 单项失败不回滚其他成功项；
- 同一设备识别来源云项目，不重复制造本机项目；
- 云端删除是独立主动操作，“全部保存到本地”本身不删除云端。

## 阶段 6：正式公开基础设施与合规检查

**状态：正式收费前必须完成。**

包括：

- 正式 SMTP；
- SPF / DKIM / DMARC；
- 注册确认、重发确认、忘记密码；
- 生产 migration 版本清单；
- Supabase 权限与 Security Advisor；
- Turnstile；
- 体验到期 Cron / 清理任务；
- 退款两阶段流程；
- 法律页面、运营主体、公示信息、跨境说明；
- Android / Web 中文、英文验收；
- 生产监控和异常支付人工处理路径。

完成前保持搜索索引和大范围推广关闭。

## 阶段 7：小范围正式收费运行

**状态：阶段4-6完成后。**

- 先邀请少量真实用户。
- 开通真实 PayPal / 支付宝订单。
- 观察注册、付款、开通、容量、退款、到期和客服问题。
- 修复实际问题后再扩大公开范围。
- 最后再评估开启搜索引擎收录。

## 阶段 8：第二阶段产品能力

**状态：首发稳定后。**

优先顺序：

1. 本地当前适种筛选：结合已有指引中的温度、播种季节和环境条件，支持“现在适合播什么”。
2. 高频实操指引继续深化。
3. 地区经验地图与相似气候经验。
4. 商社会员：商家主页、商品／服务目录、试种招募、成员协作。
5. 再往后才考虑自动化灌溉、传感器、AI 辅助和机器人照料。
